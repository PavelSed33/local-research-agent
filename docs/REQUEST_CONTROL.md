# Дедлайн и отмена рабочих запросов

Рабочий API 1.9 выполняет `/ask`, `/review`, `/review/legal`, `/extract`, `/diff`
и `/case-law/check` и `/legal/skills/run` в отдельных процессах. `API_REQUEST_TIMEOUT_SECONDS=300`
задаёт единый бюджет вычисления, включая запуск процесса, поиск, повторные обращения
и модель. Допустимо число больше 0 и не больше 3600 секунд. Это серверный предел:
клиент не может увеличить его заголовком или телом запроса.
Отдельный таймаут чтения HTTP-заголовков и тела — 30 секунд; он не входит
в бюджет вычисления, который начинается после чтения JSON. Локальные анкеты,
матрица покрытия и управление сессиями не вызывают внешние сервисы.

Клиент может передать уникальный `X-Request-ID` из 16–64 латинских букв,
цифр и дефисов. Если заголовка нет, сервер генерирует идентификатор. Ответ
возвращает его в одноимённом заголовке. Для отмены нужен тот же идентификатор
и та же авторизация сервиса:

```http
POST /requests/cancel
Authorization: Bearer <API_TOKEN>
Content-Type: application/json

{"request_id": "47b1960f-8ffd-44d7-98a9-41e6f22f432a"}
```

Идентификатор из примера замените новым UUID для каждого запуска.
Ответ `cancelled: true` означает принятие отмены, а не доказательство отзыва
запроса у провайдера. Родитель проверяет отмену примерно каждые 50 мс,
завершает и дожидается дочернего процесса и удаляет его временный каталог.
Рабочий запрос получает HTTP 409 с `code=request_cancelled`; дедлайн —
HTTP 504 с `code=request_deadline`. Успешно завершённый запрос даёт
`cancelled: false`. Работа, уже принятая внешним сервисом, может продолжиться
на его стороне и тарифицироваться; локальная отмена этого не отзывает.

Для гонки «отмена пришла раньше рабочего POST» сохраняется короткая запись
об отмене. Идентификаторы завершённых/отменённых запросов хранятся 120 секунд,
не более 1000 записей; в этом окне повторный запуск того же ID запрещён.
Отмена не является постоянным запретом повторения: всегда создавайте новый UUID.
Максимум три вычислительных процесса оставляют четвёртый HTTP-обработчик для
управления. При занятости вычислителей возвращается 429. Четыре медленных
HTTP-соединения по-прежнему могут занять общий лимит до истечения их таймаута.

Память сессий обновляет только родительский процесс после успешного результата.
Удалённая/пересозданная сессия не восстанавливается старым запросом.
Отменённая/просроченная работа не публикует постоянные отчёты даже при
`API_PERSIST_RESEARCH=true`. Остановка сервера и SIGTERM отменяют активную работу.
Это не гарантирует безопасное стирание файлов или уничтожение копий у провайдера.

API_TOKEN общий для сервиса: изоляции владельцев запросов и пользователей нет.
Не раскрывайте идентификаторы другим пользователям общего сервиса. Без токена
доступ разрешён только при loopback-прослушивании, как и раньше.

## Интерфейс и приёмка

В форме есть кнопка «Отменить». На время работы элементы формы и переключения
режима отключаются; прежний результат скрывается, чтобы ошибочный запрос
не выглядел как успешный. Неподтверждённая сетевым ответом отмена обозначается
отдельно. Завершение на сервере раньше отмены не выдаётся за остановку вычисления.

`test_request_jobs.py` проверяет настоящее HTTP-взаимодействие и дочерние
процессы с намеренно зависающим локальным тестовым LLM: дедлайн, отмену,
авторизацию, раннюю отмену, повтор ID, занятость, освобождение ресурса,
очистку файлов, публикацию успешных отчётов, защиту удалённой сессии и остановку.
Тестовые значения не являются рабочими ключами провайдеров.

Для отдельной браузерной проверки установите Playwright и Chromium в тестовой
среде (это необязательная зависимость проверки, не агента). Запустите локальный
API, затем:

```bash
BROWSER_SMOKE_URL=http://127.0.0.1:8080 node scripts/browser_smoke.cjs
```

Для API с токеном задайте `BROWSER_SMOKE_TOKEN` через окружение. Проверка использует
только синтетические документы и demo-запросы. Она проверяет пустой ввод,
результат вопроса, реальное скачивание и содержимое JSON, загрузку DOCX,
повреждённый DOCX, скрытие старого ответа, раннюю отмену, повтор после отмены,
ширину 390 px и отсутствие JS-ошибок. Отмена в браузерном сценарии задерживается
до отправки на сервер; отмена работающего процесса проверяется HTTP-тестами выше.
Она не заменяет визуальную приёмку всех экранов и реальную интеграцию провайдеров.

На 08.11.2026 браузерный сценарий **не выполнен**: локальный Chromium отсутствует,
его загрузка вернула HTML вместо ZIP, а облачный браузер не смог открыть локальный
сервер (`ERR_HTTP_RESPONSE_CODE_FAILURE`). HTTP-тесты и проверка JS-синтаксиса
не считаются успешной браузерной приёмкой. Docker и юридическая приёмка также
остаются отдельными открытыми пунктами.
