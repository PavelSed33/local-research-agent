# LAW-02–04: уточнение вида договора до специальной проверки

API 1.5. Обновлено 7 ноября 2026 года.

Выбор в поле `contract_type` отражает позицию пользователя, а не устанавливает правовую квалификацию. Перед запуском специализированного плана агент собирает дополнительные обстоятельства. Вопросы и допустимые ключи фактов возвращает `GET /review/options`; интерфейс использует этот же ответ сервера, без отдельной копии перечня вопросов.

| Тип | Дополнительный вопрос | Ключ facts |
|---|---|---|
| Поставка | Цель приобретения не связана с личным, семейным или домашним использованием? | `goods_nonpersonal_purpose` |
| Аренда | Предусмотрено временное владение или пользование имуществом за плату? | `temporary_use_for_fee` |
| Услуги | Предусмотрены оплачиваемые действия или деятельность? | `paid_activity` |
| Подряд | Предусмотрены выполнение работы и сдача результата заказчику? | `result_handover` |

Для этих четырёх типов также задаются `mixed_contract` и `special_regime`. Примеры в вопросе о специальном режиме служат подсказками для сбора обстоятельств, не являются исчерпывающим перечнем и не устанавливают применимую норму.

- Пропущенные ответы и `null` приводят к `needs_facts`, без подстановки значения «нет».
- Отрицание основного признака, заявленные смешанные элементы или специальный режим приводят к `needs_qualification`. Договор не переквалифицируется автоматически, и нарушение не устанавливается.
- При заявленной личной цели в потребительском профиле выбранная поставка отправляется на уточнение даже при противоречащем ей ответе о неперсональной цели.
- До уточнения специализированные карточки перемещаются в `checklist.deferred_rules`; активный `checklist.rules` пуст. Модель, поиск и проверка разрешения внешней передачи не вызываются, текст договора не отправляется наружу.
- Согласованные ответы допускают только черновик с `candidate_type`, `verified=false`. Ответы пользователя не подтверждают закон, редакцию, содержание самого договора и итоговую квалификацию.
- Общий режим возвращает `general_scope_only`: он не обещает проверки всех специальных договоров. Явно заявленный смешанный или специальный режим сохраняет необходимость квалификации и в общем режиме.
- Трудовой профиль использует только `general` и не получает гражданские вопросы о виде договора. Проверка трудовой связи и профильных фактов остаётся отдельной.

Статус профиля и статус вида обязательств разделены: например, отсутствие личной цели может дать `applicability.status=scope_mismatch`, одновременно с недостающими фактами по типу. Противоречия не скрываются за общей отметкой успешной проверки.

## Пример запроса

```json
{
  "document": "Текст договора подряда для исследования, не менее двадцати символов.",
  "profile": "business",
  "contract_type": "work",
  "demo": true,
  "facts": {
    "both_businesses": true,
    "result_handover": true,
    "mixed_contract": false,
    "special_regime": false
  }
}
```

Это технический пример запроса, не юридическая эталонная задача. Если убрать ответы о смешанных элементах/специальном режиме, запрос вернёт вопросы. В рабочем режиме для продолжения по-прежнему нужны настройки провайдеров и разрешение передачи договора; юридическая применимость не считается установленной.

## Источник исследования и ограничения

7 ноября 2026 года веб-инструмент получил текст официального PDF [Пленума ВС РФ №49 от 25.12.2018](https://www.vsrf.ru/files/27530/). В корпус сохранено извлечение только пункта 47: строки 619–630 веб-извлечения, индекс страницы 14 (печатная страница 15). В нём квалификация связана с содержанием и признаками обязательств, а не одним наименованием договора. Это судебное разъяснение, не исходный текст статей ГК РФ и не подтверждение их редакций.

Файл `fixtures/legal_evidence/vsrf-49-point47.txt` и манифест сохраняют SHA-256 и точное положение цитаты. Исходные байты PDF и HTTP-ответ не архивированы. Особенности извлечения надстрочных обозначений не исправлялись молча. Сохранение одного пункта не означает полноты постановления, истории изменений или юридической приёмки.

Материал связан с исследовательской карточкой LAW-02:421 и может использоваться как неполный локальный источник при соблюдении общего ограничения корпуса по дате получения. Статусы первичного текста статьи, периода и юридической проверки остаются неподтверждёнными. Тесты этого этапа проверяют блокировку запросов, сохранение пробелов и техническую корректность, а не заменяют реальные задачи, утверждённые юристом.
