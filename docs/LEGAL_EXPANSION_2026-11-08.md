# Расширение законодательства и рабочих сценариев

Дата исследования: 8 ноября 2026 года. Базовый коммит: `1dbe7afad32fd0086ea44c8fc7c655d5496e2aa8`.

Добавлены конкретные нормы, полученные тексты, рабочие анкеты и связь с ответами
агента. Каждый из 454 элементов имеет извлечение нормативного текста; число
извлечений не является числом юридически принятых норм. Приёмка всех модулей
остаётся открытой. Данная страница описывает текущее расширение; более ранние
документы и журналы README сохраняют историю предыдущих этапов.

## Источники и границы достоверности

`fixtures/statute_corpus/` содержит 15 групп извлечений и манифест. Для каждой
статьи или раздела записаны точный URL, акт, положение, заголовок, извлечённый
текст, дата получения, SHA-256 текста и SHA-256 фактически полученного HTTP-тела.
Сохранена наблюдаемая метка редакции, если она была в странице.

Основной корпус — **справочные копии**, а не оригинальные официальные публикации.
Редакционные вставки справочной системы, навигация и скрипты исключены. Пробелы
нормализованы; полнота каждого извлечения не удостоверена. Исходные HTTP-тела
использованы для извлечения и хеширования, но не архивированы в репозитории.
Хеш не доказывает подлинность источника, полноту истории или применимость нормы.

В существующий корпус судебных материалов добавлен выбранный абзац
[Пленума ВС РФ от 29.09.2015 № 43](https://www.vsrf.ru/documents/all/8453) о начале
исковой давности. Цитата и её положение проверяются по сохранённому тексту.
Это разъяснение суда, а не первичный текст статьи 200 ГК РФ и не полный акт.

Попытки получения отдельных официальных источников давали 403/503; их нельзя
считать полученными оригинальными публикациями. В частности, получение
справочной копии приказа № 179 не закрывает получение оригинала записи
`0001202211290008`. Ранее созданная карта поправок к статьям 3, 6 и 9 152-ФЗ
не объявляется полной и не повышается до `verified` новым корпусом.

## Поведение агента

- `/ask`: локальный поиск по установленному акту, точному номеру статьи и словам
  заголовка. Копии могут дополнить первоначальный поиск в пределах лимита
  источников; обязательные проверки поправок и судебных материалов сохраняются.
- `/review/legal`: дополнительные вопросы по профилю и типу договора; отдельные
  локальные статьи для общего и специального режима. Число материалов ограничено,
  одна статья сохраняет собственный URL. Свежие поисковые результаты сохраняют
  первые номера источников. Договор не включается в поисковые запросы.
- `/legal/coverage`: показывает карточки, полученные тексты, происхождение и
  открытые пробелы раздельно. Принятых положений по-прежнему ноль.
- `/legal/research`: 35 локальных сценариев. Даже все ответы «да» приводят к
  `needs_legal_review`; ответы «нет» не превращаются автоматически в нарушение.
- `/legal/corpus`: метаданные либо запрошенные тексты. Для текста требуется от
  1 до 50 конкретных `card_ids`. API не принимает URL или локальный путь для загрузки.

Позднее получение копии не подтверждает историческую редакцию. Снимки после
даты ситуации исключаются из контекста модели, но могут отображаться в отчёте
как более поздние материалы с соответствующей меткой. Нет автоматического
расчёта сроков, штрафов, пошлины или криптографического подтверждения подписи.

## Примеры API

При настроенном API_TOKEN нужен `Authorization: Bearer …`.

```json
POST /legal/research
{"scenario":"civil-limitation","as_of":"2026-11-08","facts":{}}
```

```json
POST /legal/corpus
{"card_ids":["LAW-02:165.1","LAW-06:gpk:56"],"include_text":true,"as_of":"2026-11-08"}
```

```json
POST /legal/coverage
{"module_ids":["LAW-07"],"as_of":"2026-11-08"}
```

Список сценариев и допустимых фактов: `GET /legal/research/options`.
Документы и произвольные строки вместо логических фактов отклоняются.

## Воспроизведение и обновление

```sh
python scripts/validate_legal_data.py
python statute_corpus.py
python legal_evidence.py
python -m unittest discover -q
python scripts/acceptance.py
```

Обновление — явная команда оператора, без расписания и автоматического признания
новой редакции. Пример полного обновления:

```sh
python scripts/fetch_statutes.py --all --output-dir /tmp/legal-statute-staging
python scripts/import_statutes.py /tmp/legal-statute-staging
python scripts/validate_legal_data.py
```

Для выборочной загрузки вместо `--all` можно повторять `--card-id LAW-02:165.1`.
Загрузчик использует закреплённые URL полученных статей, максимум четыре
параллельных запроса и ограниченные ответы. Произвольные адреса, перенаправления
на другие хосты и незащищённый транспорт запрещены. Новые акты и новые URL требуют
отдельного исследования и изменения реестра; это не автоматический поиск поправок.

При неудачном обновлении старое извлечение сохраняется с прежней датой получения,
а пробел виден в `refresh_gaps`. Нельзя считать повторную проверку свежим получением
текста. В staging находятся исходные HTML; хранение этих файлов определяет оператор.

## Контрольные задачи и незавершённые проверки

В `fixtures/legal_benchmarks.json` подготовлены **90 синтетических черновиков** —
по десять на модуль. Есть недостаток фактов, неверная квалификация, конфликт дат,
старый договор и поздний судебный акт. Для известных исследовательских границ
согласия и потребительских условий включены день до, день изменения и день после.
Каждый случай содержит факты, дату, ссылки на карточки и запрещённый вывод.
Утверждённых юридических ответов, имени проверившего юриста и согласования нет;
это очередь приёмки, а не доказательство качества реальных ответов модели.

До заявления о юридически проверенном покрытии остаются:

1. Получение и сверка первичных публикаций и полных цепочек поправок, включая
   переходные положения, специальные даты и периоды действия выбранных норм.
2. Уточнение частей и пунктов, исключений, специальных договорных и отраслевых
   режимов. Выбранные статьи не составляют полное законодательство РФ.
3. Утверждение эталонных ответов юристом и оценка реальных ответов модели.
4. Проверка реальных провайдеров с конфигурацией владельца и оценка фактических
   потоков данных сервиса. Флаг разрешения облака не является правовым основанием.
5. Реальный запуск Docker и браузерная проверка интерфейса; локальная проверка
   комплектации файлов не заменяет эти испытания.

В текущей среде Docker отсутствует. Автоматические технические проверки
описываются отдельно в журнале изменений/PR; успешный тест не повышает
`verified`, `period_supported` или результат юридической приёмки.
