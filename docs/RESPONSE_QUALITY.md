# Оценка сохранённых ответов — API 1.12

Контур `scripts/evaluate_answers.py` проверяет сохранённые ответы без модели,
поиска и внешних запросов. Поддерживаются ответы `/ask`, `/review` и
`/review/legal`. Это техническая проверка структуры и соответствия цитат,
а не оценка истинности всех выводов или замена юридической приёмки.

## Подготовка материалов

Для `/ask` задайте `include_source_materials:true` либо включите в интерфейсе
«Включить тексты источников в JSON для проверки». По умолчанию экспорт текстов
выключен. В JSON добавится `source_materials`: номер, название, URL, текст
использованного материала, SHA-256 и дата экспорта. Поисковые запросы и журнал
не включаются. Материалы ограничены сохранённым фрагментом до 9000 символов,
который используется в контексте ответа; это не сырой HTTP-ответ и не полный
оригинал публикации. Дата экспорта не является датой получения/публикации
первоисточника или началом действия редакции.

Экспорт может содержать сведения из материалов исследования; он сохраняется
только по решению пользователя при скачивании JSON. Сервисный флаг постоянного
хранения результатов не меняется. Вопрос, документы и ответы не передаются
новому сервису оценки — она работает локально.

Скачанный ответ оберните в набор случаев, например локальным Python:

```python
import json
from pathlib import Path

response = json.loads(Path('answer.json').read_text(encoding='utf-8'))
bundle = {'schema_version': 1, 'cases': [
    {'id': 'case-001', 'kind': 'ask', 'response': response}
]}
Path('answer_bundle.json').write_text(
    json.dumps(bundle, ensure_ascii=False), encoding='utf-8')
```

Запуск:

```sh
python scripts/evaluate_answers.py answer_bundle.json
```

Для договорного анализа используйте `kind:"review"` или `kind:"legal_review"`
и передайте исходный текст договора в `document` рядом с `response`.
Для `legal_review` отдельно задайте `source_materials` с полями `id`, `title`,
`url`, `text`, `sha256`; они должны соответствовать порядку и URL `response.sources`.
Хеш — SHA-256 UTF-8 текста. Материалы из ответа без текста и контрольной суммы
не считаются достаточными. Недостающие тексты автоматически не скачиваются.

Можно указать ожидаемую `as_of` для ответа и `benchmark_id` из 90 задач
`fixtures/legal_benchmarks.json`. Связь с ID не доказывает соответствие фактов
или качество ответа: это проверяет человек. Переопределение даты связанной
эталонной задачи фиксируется как ошибка. Набор ограничен 200 случаями и 8 МиБ;
на случай — до 16 материалов, текст ответа/документа до 200000 символов.

## Проверки и границы

- Структура отчёта, ссылки на допустимые номера и URL источников.
- Связь упомянутой статьи и конкретного акта с цитируемым источником.
- Дословные цитаты договора и правовых оснований в структурированном разборе.
- Совпадение номера, URL, названия и SHA-256 сохранённого материала.
- Сохранение запрошенной даты ситуации.
- Недопустимое повышение `verified`, `lawyer_reviewed`, `period_supported`
  и `legal_acceptance`, включая вложенные поля.
- Отсутствующие документы/материалы, демоответы и незавершённые разборы
  не превращаются в успешно оценённые рабочие ответы.

Хеш подтверждает согласованность предоставленного снимка, а не подлинность
источника. Существование статьи и совпадение цитаты не доказывают, что вывод
правилен, все существенные факты учтены или редакция применима. Проверка
не оценивает полноту извлечения фактов, семантику каждого правового вывода,
полноту цепочки поправок и устойчивость практики.

В отчёте нет процента юридической готовности. Есть `technical_counts` и статусы:
`passed`, `failed`, `blocked`. Поля `model_execution_verified`,
`source_authenticity_verified`, `lawyer_reviewed` и `legal_acceptance` остаются
false даже при прохождении всех технических проверок. Флаг демо блокирует
учёт такого ответа как рабочего; произвольно выставленное demo=false само
по себе не доказывает реальный вызов модели.

Указание утверждённого эталона лишь отмечает заявленную человеком проверку;
автоматического смыслового сравнения с ним нет. Текущие 90 задач не имеют
утверждённых ответов и остаются черновиками. Итог всегда требует независимой
юридической оценки.

CLI возвращает 0 только при прохождении технических проверок, 1 — при ошибках,
2 — при блокировках или некорректном наборе. Это не коды юридического допуска.
Отчёт содержит ID случаев и коды проверок, без повторения текста документов,
цитат, URL или произвольных сообщений об ошибках. Используйте обезличенные ID.

## Воспроизводимый пример

```sh
python scripts/evaluate_answers.py fixtures/response_quality_examples.json
python -m unittest test_response_quality -q
```

В примере два искусственных ответа, а не результаты реального провайдера.
Шаг CI явно помечен как проверка синтетических снимков. Сам по себе зелёный
результат этого шага не подтверждает юридическое качество агента.
