# Пилот проверки договора услуг — API 1.24

Первое направление — возмездное оказание услуг в предпринимательских отношениях.
Пилот формирует черновик для юриста. Смешанные договоры, специальные режимы и
непредпринимательский профиль возвращаются на уточнение квалификации.

## Сценарий в интерфейсе

1. Подключитесь к `/workspace` индивидуальным токеном, выберите дело.
2. Загрузите и сохраните договор; при необходимости добавьте приложения и
   переписку. Сценарий включает весь сохранённый текст выбранного договора,
   максимум 20000 символов. Превышение возвращает явную ошибку без обрезки.
3. В форме «Сопоставить документы» задайте вопрос и дату ситуации. Раскройте
   «Пилот: договор услуг между предпринимателями», включите режим, выберите
   сохранённый договор и ответьте на четыре вопроса. «Не установлено» не
   превращается в отрицательный ответ.
4. Подготовьте источники норм и досье редакций на дату, передайте их другому
   проверяющему и выберите необходимые нормы в форме. Приложение учитывает запись
   проверки, но не удостоверяет квалификацию человека. Нельзя использовать один
   документ одновременно как договор и выбранную редакцию нормы.
5. Без фактов возвращается `needs_facts`, при конфликте профиля —
   `needs_qualification`, без выбранных норм — `needs_sources`. Модель не вызывается.
6. Режим «Показать фрагменты без модели» возвращает только демонстрацию цитаты.
   Для рабочего вызова выключите его. Для удалённой модели нужны одновременно
   разрешение запроса и серверное разрешение передачи документов; настройки
   автоматически не меняются.
7. Проверьте разбор в предпросмотре и скачайте тот же UTF-8 Markdown. Перед
   скачиванием повторно проверяются доступ, хеши источников и состояние выбранных
   редакций. При смене параметров, пользователя или дела отчёт сбрасывается.

## Структура вывода

Каждый вывод содержит вид, оценку, объяснение применимости, следующий шаг и
дословные цитаты с документами, SHA-256, смещениями и страницами фрагментов.

| Вид | Минимальные технические требования |
|---|---|
| Наблюдение | Цитата выбранного договора |
| Кандидат на правовой риск | Цитата договора и цитата источника с выбранной редакцией на дату |
| Предполагаемое противоречие | Цитаты минимум двух разных документов, включая договор |
| Недостающие сведения | Связь с цитатой договора и объяснение, что запросить |

Это проверка структуры и точности цитирования. Совпадение цитаты не доказывает,
что норма подтверждает вывод, правильно выбрана статья или учтены все исключения.
`semantic_support_verified`, `verified`, `lawyer_reviewed`, `legal_acceptance`
остаются `false`. Пустой список выводов не объявляет договор безопасным.

Один ответ содержит до 20 выводов и до 8 цитат на вывод; Markdown ограничен
512 КиБ без скрытого усечения доказательств. Недоверенный текст выводится как
текст, а в Markdown помещается в блоки с защищёнными границами.

## API

Используется существующий `POST /workspace/ask` с полями:

```json
{
  "matter_id": "<дело>",
  "question": "Какие условия оплаты и приёмки требуют проверки?",
  "analysis_mode": "services_pilot",
  "contract_document_id": "<сохранённый договор>",
  "as_of": "2025-06-30",
  "facts": {
    "both_businesses": true,
    "paid_activity": true,
    "mixed_contract": false,
    "special_regime": false
  },
  "editions": [],
  "demo": true,
  "allow_cloud": false
}
```

Пустой `editions` намеренно возвращает `needs_sources`. Допускается до трёх
ссылок `{act_id, provision}`; каждая выбирается существующим механизмом редакций.
Неоднозначный период, отозванная проверка и неподходящая дата останавливают запрос.
Общий режим анализа документов остаётся доступен без новых полей.

`POST /workspace/analysis/validate` получает `matter_id`, `as_of`, `documents`
из `{document_id, sha256}` и `editions` из `selected_editions` ответа. Возвращает
только актуальность технического контекста. Он не удостоверяет подлинность
находящегося у клиента отчёта и не подписывает юридические выводы. В журнал
записывается факт проверки без текстов и секретов.

## 25 заданий для независимой приёмки

В разделе экспертных заданий нажмите «Добавить 25 заданий по услугам».
Задания `SERV-P01`–`SERV-P25` импортируются отдельно; прежний импорт 90 задач
не меняется. Повторный импорт не дублирует записи.

Каждое задание содержит синтетический договор, вопрос, иногда дополнительный
документ, заявленные обстоятельства, темы поиска, рубрику проверки и недопустимый
вывод. Поле `approved_legal_answer` пусто, одобрений нет. Темы и рубрики не являются
утверждёнными правилами права. Реальных проверенных юридических эталонов этим
изменением не добавлено.

Темы: объём и приложения, цена и налоговая оговорка, оплата и аванс, сроки,
приёмка и возражения, третьи лица, отказ сторон, ответственность и неустойка,
изменение тарифа, электронные сообщения, полномочия, конфиденциальность,
исторические даты, смешанный договор, специальный режим, потребительский профиль
и команды внутри недоверенного документа.

Эксперт должен подобрать реальные первичные источники и редакции, ввести
ожидаемый ответ, обязательные риски и точные цитаты. Затем другой проверяющий
принимает или возвращает материал через существующую очередь. Для оценки реальных
ответов используйте корректность, пропущенные риски и неподтверждённые утверждения;
не заменяйте эти показатели числом технических тестов.

## Проверки и открытые условия

```sh
python -m unittest test_service_pilot test_workspace_report_ui test_benchmark_tasks -v
python scripts/pilot_acceptance.py --live
```

Тестовый HTTP-сценарий проходит через настоящий дочерний процесс и локальный
синтетический OpenAI-совместимый сервер. Это проверка транспорта, схемы, цитат
и доступа, а не настоящей модели и не юридического качества.

Поиск дополнительных документов остаётся лексическим FTS5. Семантический поиск,
полные истории законодательства и судебных цепочек этим этапом не добавлены.
Полнота исходного DOCX/PDF после извлечения, приложения и смысловая поддержка
каждого вывода требуют проверки. Настоящая модель, браузер и независимый юрист
остаются отдельными условиями пилота.
