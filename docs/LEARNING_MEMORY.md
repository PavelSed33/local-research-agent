# Обучающая память — API 1.28

Первый этап самообучения — использование исправленных экспертных примеров в
контексте следующего запроса пилота услуг. Веса модели, программный код и
правила правового анализа автоматически не меняются. Фактическое улучшение
юридического качества пока не измерено.

## Цикл работы

1. Подготовьте эталон задачи: вопрос, дату, правильный ответ, обязательные риски,
   недопустимые выводы и цитаты. Другой пользователь с ролью эксперта проверяет
   и одобряет его через существующую очередь. Приложение регистрирует решение,
   но не удостоверяет квалификацию человека.
2. Получите ответ агента и запишите экспертную оценку: правильность 0–4,
   пропущенные риски и неподтверждённые утверждения. Используйте метку запуска.
3. Включите «Использовать одобренный опыт этого дела» в пилоте услуг. Кнопка
   «Показать доступный опыт без модели» позволяет сначала проверить подборку.
4. В следующий рабочий запрос попадут исправленный эталон и перечень рисков,
   а не сам ошибочный ответ. Агент должен заново проверить применимость и
   обосновать правовые риски выбранными редакциями норм.
5. Сравнивайте ответы без памяти и с памятью на отдельных контрольных задачах.
   Исключите все контрольные эталоны из подбора по идентификаторам. Для метрик
   используйте существующие экспертные оценки и общие задачи разных меток запуска.
   Результаты, полученные с подсказанным эталоном, не являются независимой оценкой.

## Что допускается в память

Подбираются только одобренные эталоны этого же дела с **точно той же датой**.
Нужна оценка, связанная с текущей записью одобрения, в которой правильность ниже 4,
есть пропущенный риск или неподтверждённое утверждение. Цитаты и хеши документов
перепроверяются. Положительная оценка без ошибок сама по себе пример не добавляет.

Подбор использует пересечение слов вопроса длиной от трёх символов. Это простой
лексический поиск, а не доказательство сходства юридических обстоятельств.
Просматривается до 100 последних эталонов и до 101 записи оценки каждого;
результат ограничен тремя примерами по 10000 символов сериализованного JSON.
Слишком большие примеры пропускаются целиком. Признак `candidate_limit_reached`
сообщает о превышении числа эталонов; полнота поиска не гарантируется.

Неодобренные материалы, чужие дела, другие даты, старые оценки после повторного
одобрения и явно исключённые эталоны не используются. Точное совпадение вопроса
с эталоном также исключает его. Это не выявляет все перефразирования и не заменяет
разделение обучающего и контрольного наборов.

## API и журнал происхождения

`POST /workspace/learning/preview` принимает `matter_id`, `question`, `as_of` и
необязательный `learning_exclude_artifact_ids` — до 100 различных идентификаторов.
Модель и поиск в интернете не вызываются. Ответ содержит `examples`, `references`,
`used_count`, `weights_updated=false` и ограничения. Ошибочные ответы и заметки
проверяющего не копируются в подсказку. Данные уже хранятся в эталонах и оценках;
новой схемы БД или отдельной копии обучающего корпуса нет.

Для рабочего запроса `POST /workspace/ask` включите:

```json
{
  "analysis_mode": "services_pilot",
  "use_learning": true,
  "learning_exclude_artifact_ids": ["<идентификатор контрольного эталона>"]
}
```

Остальные обязательные поля пилота сохраняются. Память выключена по умолчанию;
в общем режиме она не поддерживается. `learning_context.used_count` — число
подобранных примеров, а `learning_applied` показывает, были ли они переданы модели.
В деморежиме, при недостатке фактов или норм `learning_applied=false`.

Каждый пример связан с хешем эталона, точной записью его одобрения и хешем оценки.
Отзыв/повторное одобрение или изменение оценки блокирует выдачу результата,
использовавшего прежнюю версию опыта, в том числе скачивание сохранённого отчёта.
Маршрут `/workspace/analysis/validate` проверяет только переданный контекст
источников; для сохранённого отчёта используйте `/workspace/analysis/read`.

Примеры передаются в `learning_context`, а не добавляются к нормативным `sources`.
Они не могут заменить выбранную редакцию, создать подтверждение нормы или снять
требование цитат. Исправленный ответ тоже является недоверенным текстом, а не
командой модели. В Markdown отмечаются подобранные примеры и факт их передачи.

## Практические ограничения

Реальных принятых юристом примеров этим изменением не создано. При их отсутствии
подборка будет пустой; синтетические технические тесты не доказывают обучение на
реальных ошибках. Не запускаются дообучение весов, загрузка данных в сторонний
тренировочный сервис или автоматическое принятие новой версии агента.

Если разрешена облачная модель, примеры этого дела входят в отправляемый ей
контекст вместе с другими материалами. Действуют существующие разрешения
`allow_cloud` и серверное разрешение передачи документов. Смена пользователя или
дела сбрасывает включение памяти и список исключений в интерфейсе.
