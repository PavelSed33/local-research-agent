# LAW-07: наблюдаемые потоки данных сервиса

Дата анализа кода: 7 ноября 2026 года. Карта относится к текущему исходному коду API, а не к фактически развёрнутой инфраструктуре. Оператор, поставщики услуг, договоры с ними, страны обработки и основания операций не установлены. Юридического заключения о соответствии 149-ФЗ/152-ФЗ нет.

| Поток | Передаваемые данные и получатель | Наблюдаемые ограничения в коде | Что ещё установить |
|---|---|---|---|
| `POST /ask` → LLM | Вопрос, история выбранной сессии, правовые материалы и промежуточные задания → настроенная модель | Деморежим работает без внешней модели; HTTP-ошибки не раскрывают тело ответа провайдера | Вопрос и история могут содержать персональные данные. Флаг ALLOW_CLOUD_DOCUMENTS не регулирует этот маршрут; нужны отдельные основания и правила допустимого ввода |
| `POST /ask` → поиск | Сформированные моделью поисковые запросы → Tavily; возможны прямые запросы к правовым источникам | Ограничены число запросов, время, объём ответа; исходные темы не становятся обезличенными автоматически | Проверить состав фактических запросов, получателей, основание раскрытия и страны обработки |
| `/review`, `/extract`, `/review/legal` → модель | Текст договора и задание → LLM_BASE_URL | Перед рабочей отправкой проверяется локальность адреса или ALLOW_CLOUD_DOCUMENTS; в деморежиме передача отсутствует | Наличие настройки не подтверждает согласие субъектов, поручение, основания, локализацию, трансграничные требования или безопасность провайдера |
| `/review/legal` → поиск | Общий профиль, тип договора, ссылки на нормы и дата → Tavily | Текст договора не включается в поисковую строку этого маршрута; это проверяется тестом | Сам договор по-прежнему передаётся модели; конкретное поведение и хранение поискового провайдера требуют проверки |
| `/case-law/check` → модель/поиск | Вопрос и найденные судебные материалы → модель и поиск | Деморежим без внешних запросов; цитаты реквизитов проверяются отдельно | Пользовательский вопрос и судебные материалы могут содержать данные физических лиц; публикация судебного акта не доказывает право любой последующей обработки |
| `/diff` | Обе редакции → локальное извлечение и сравнение | Модель/поиск не вызываются; DOCX разбирается в памяти | Защитить доступ к серверу, памяти процесса, исходным файлам пользователя, устройству и скачанным результатам |
| `/privacy/check`, `/legal/coverage` | Предопределённые ответы и дата / выбор модулей → локальная обработка | Эти маршруты не вызывают модель/поиск, не создают сессии и файлы результатов. Анкета не принимает документы и произвольные поля фактов | Ответы не являются доказательствами и не подтверждают правомерность иной обработки |
| Локальный правовой корпус | Избранные строки публичных источников → файлы проекта и образ контейнера | SHA-256, ограничение размера, проверка путей и точных положений цитат; повреждённые записи исключаются | Это прерывистые веб-извлечения, не исходные HTTP-ответы; подлинность, полнота и юридическая применимость не удостоверены |
| История сессии `/ask` | Вопрос и сокращённый ответ → память процесса при переданном session_id | Лимиты числа сессий/записей; срок неактивности по умолчанию 3600 секунд; очистка просроченных записей при обращении к хранилищу; отдельное удаление с защитой от восстановления незавершённым запросом | Это не фоновое уничтожение ровно через час. Удаление сессии не удаляет файлы, копии у провайдеров, данные браузера или резервные копии |
| Результаты `/ask` | Отчёт и журнал → файловая система сервера | В HTTP API по умолчанию временный каталог удаляется после обработки. Постоянное хранение включается отдельно. Прямой Python-вызов handle_ask по умолчанию сохраняет файлы; CLI тоже создаёт отчёты | Постоянные результаты не имеют автоматического юридически назначенного срока хранения; очистка временного каталога не гарантирует физическое стирание носителя |
| HTTP/инфраструктурные журналы | Метод, путь, адрес клиента, статус и технические ошибки → stderr/среда запуска | Код не записывает тела успешных HTTP-запросов в журнал доступа; неожиданные ошибки выводятся по типу | Reverse proxy, контейнерная платформа, провайдер и администратор могут вести дополнительные журналы; их состав и сроки неизвестны |
| Веб-интерфейс и скачивание | Значения формы/токен/результат → память страницы; JSON при скачивании → устройство пользователя | Токен и результаты не записываются приложением в localStorage; сервер задаёт no-store для UI; отображение через textContent | Данные остаются в DOM до очистки/закрытия страницы; скачанные файлы, расширения браузера и системные резервные копии вне контроля приложения |

## Очередь проверки конкретного развёртывания

1. Установить оператора и роли всех получателей, включая администратора сервера, поставщиков модели, поиска и хостинга.
2. Составить перечень категорий субъектов, данных, целей, операций и оснований отдельно для каждого потока. Не предполагать, что все операции основаны на согласии или что один документ покрывает их все.
3. Подтвердить территории баз данных, обработки, резервного копирования и поддержки; адрес API и доменная зона не удостоверяют страну обработки.
4. Проверить необходимые поручения, договорные условия, уведомления и ограничения по актуальным нормам на дату ситуации.
5. Назначить сроки и события окончания хранения для памяти, постоянных отчётов, журналов и копий у провайдеров; отдельно организовать выполнение требований субъектов и подтверждение удаления.
6. Определить модель доступа, владельцев журналов, порядок реагирования на инциденты и состав доказательств выполнения обязанностей.
7. Пройти юридическую проверку по ограниченному сценарию LAW-07. Пока эти сведения и источники не получены, модуль не принят.

Основания наблюдений: `api.py` (SessionStore, handle_ask, create_server), `agent.py` (run, LLM и поиск), `doctext.py`, `legal_review.py`, `review.py`, `extract.py`, `redline.py`, `case_law.py`, `privacy_review.py`, `web/app.js`. Конкретные обязанности, исключения и сроки закона по этой технической карте автоматически не назначаются.
