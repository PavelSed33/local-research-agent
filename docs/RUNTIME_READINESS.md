# Проверка готовности функций

В API 1.10 добавлен `GET /runtime/readiness`. Проверка читает настройки и
локальные файлы, не вызывает модель, поиск, Docker или браузер, не передаёт
документы и не меняет конфигурацию. При заданном API_TOKEN нужен тот же
Bearer-токен, что используется для POST. Значения ключей, названия моделей,
адреса провайдеров и локальные пути в ответ не включаются. Ответ — `no-store`.

В интерфейсе нажмите **Проверить настройку**. Результат открывается отдельно
от правового ответа. Проверка не отключает существующие функции и не даёт
автоматического разрешения на облачную передачу документов.

| Функция | Что требуется в рабочем режиме |
|---|---|
| Локальные реквизиты (`/extract/local`) | Локальные шаблоны; модель, поиск и облачная передача не нужны |
| Сравнение редакций | Локальный код, без модели и поиска |
| Анкеты, правовые сценарии, корпус и покрытие | Локальные данные; целостность проверяется отдельно |
| Реквизиты, анализ договора, два договорных навыка | Модель; существующая политика передачи документов |
| Правовой вопрос и судебные акты | Модель и поиск |
| Полный сетевой разбор договора, аудит утверждений | Модель, поиск и политика передачи документов |

Если у правового разбора договора отсутствует только поиск, но модель и
политика передачи настроены, отдельный флаг `local_fallback_can_attempt`
показывает возможность попробовать ограниченный разбор по сохранённым
извлечениям. Это существующий резервный режим, а не замена проверки актуальности.

## Как читать результат

- `ready_locally`: для локальной функции нет обнаруженных технических блокеров.
- `configured_unchecked`: настройки внешних сервисов присутствуют и их формат
  допустим; реальный вызов провайдера ещё не проверен.
- `blocked`: в `blockers` перечислены недостающие зависимости: `llm`, `search`,
  `document_transfer`, `statutes`, `evidence` или `skills`.

`can_attempt` оценивает только технические предпосылки. Входной документ,
обстоятельства и обязательные поля методики проверяются при самом запросе.
Ни один статус не подтверждает оплату/доступность провайдера, применимую редакцию,
правомерность передачи данных, полноту исследования или юридическую приёмку.
Флаги `external_services_tested` и `legal_acceptance` остаются false.

Переменные с известными значениями-заглушками или пробельными значениями не
считаются настроенными. Для локальной модели на localhost/loopback существующая
политика не требует облачного разрешения; некорректные URL всё равно блокируют
соответствующий провайдер. Ошибка настройки поиска не отключает навыки, которым
нужна только модель. Повреждение файлов навыка не отключает локальное сравнение.

CLI остаётся доступным: `python preflight.py`. Он загружает `.env` существующим
способом и выводит расширенный отчёт без значений секретов. Настройки изменяет
оператор в своей среде; интерфейс не принимает ключи LLM/Tavily и не сохраняет их.

## Контекст навыков

У каждой методики собственный набор полей. Форма скрывает ненужные поля и не
включает их в запрос. Сервер дополнительно очищает контекст: старые правила
компании и тема поиска от другой методики не передаются модели. Это действует
и для прямых API-клиентов. Обязательные поля и ограничения размеров сохраняются.
