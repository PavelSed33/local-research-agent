# Проверка внешней библиотеки российского законодательства (2026-11-09)

Кандидат: https://github.com/shodenis/Russian-Law-MCP (пакет @ansvar/russian-law-mcp).
GitHub README заявляет 12 369 актов и 77 647 статей. Это **заявление автора**, не подтверждённая юридическая полнота.

## Результаты первичной проверки

- Код: Apache-2.0 по файлу LICENSE и package.json; соблюдать NOTICE и условия лицензии.
- package.json содержит команду `ingest:ruslawod`, а также зависимость `@ansvar/mcp-sqlite` и MCP SDK. Следовательно, нельзя автоматически считать происхождение всей поставляемой базы однородным.
- Поставка включает `data/database.db`; состав и происхождение каждой записи в ней не проверены.
- Программный код, бинарная база и транзитивные зависимости **не проходили** полного аудита у нас.
- Сторонний удалённый MCP не подключать: возможна передача конфиденциальных запросов и подмена источников.
- **Решение: НЕ ИМПОРТИРОВАТЬ базу и НЕ ЗАПУСКАТЬ пакет** до проверки каждой партии и её лицензии.
- Источник RusLawOD и любые производные от него записи исключаются независимо от лицензии обёртки.

## Подготовленный механизм допуска

`scripts/check_external_corpus_manifest.py` требует для каждой партии URL, список источников происхождения, лицензию, SHA-256 и явное одобрение. Неизвестная лицензия, RusLawOD и отсутствие реквизитов блокируют импорт.

```bash
python scripts/check_external_corpus_manifest.py data/external_corpus_manifest.example.json
```

Пример намеренно блокируется: без одобренных записей импорт не разрешён. Даже успешная проверка метаданных не доказывает безопасность кода, правомерность использования и корректность документов.

## Для следующего этапа

1. Получить исходную схему SQLite, список таблиц и происхождение записей в отдельной изолированной среде без выполнения кода поставщика.
2. Проверить права на каждый источник, исключить RusLawOD, сверить выборку с официальным pravo.gov.ru.
3. Проверить SHA-256 скачанных файлов, SQL-структуру, лимиты, тесты и отсутствие утечек.
4. Только после этого импортировать одобренные записи в отдельный карантинный индекс, не в рабочие юридические ответы.
