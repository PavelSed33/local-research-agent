# Отчёт по судебному делу — API 1.20

## Результат двухчасового этапа

Реализован локальный сценарий из ТЗ `TZ_legal_agent_2_hours_2026-11-09.md`:
выбор дела и даты, проверяемый снимок загруженных судебных материалов,
предпросмотр и скачивание Markdown. Базовая версия перед изменением —
API 1.19, удалённый commit fc15b6cd8330ba133ec1756b85b760579e7be436.
Этот этап не закрывает юридическую приёмку агента.

## Как пользоваться

1. Откройте `/workspace`, подключитесь индивидуальным токеном и выберите дело.
2. Добавьте судебные документы и карточки. Для четырёх архивных определений
   выберите источник и нажмите «Создать черновик карточки».
3. При необходимости добавьте позиции, применимость и связи с уже загруженными
   актами. Ручное обозначение связи ещё не доказывает её правовой смысл.
4. В разделе судебных материалов укажите номер судебного дела и дату среза.
   Открытие карточки подставляет её номер и дату; дату можно изменить.
5. Нажмите «Сформировать отчёт», прочитайте ограничения и предпросмотр.
6. Нажмите «Скачать Markdown». Скачивается именно просмотренный UTF-8-файл.

Перед скачиванием интерфейс повторяет защищённый запрос и сравнивает отпечаток
снимка. При изменении карточек или записей проверки требуется новый предпросмотр.
При отзыве доступа файл не выдаётся, предпросмотр очищается. Смена токена,
дела, номера судебного дела или даты очищает подготовленный отчёт.
Уже скачанный пользователем файл сервер отозвать не может.

Предпросмотр — текст Markdown, не исполняемый HTML. Исходные документы
не интерпретируются как команды; модель и внешние сервисы не вызываются.

## Маршрут и формат

`POST /workspace/cases/report`, индивидуальный Bearer-токен:

```json
{"matter_id":"<id дела>","case_number":"А56-119496/2023","as_of":"2025-09-04"}
```

Разрешены только три поля; все обязательны, дата строго YYYY-MM-DD.
Право чтения требуется для выбранного рабочего дела; администратор не получает
автоматического доступа к чужому делу. Наблюдатель может сформировать отчёт.

JSON-ответ содержит:

- `report`: акты, последние версии, статусы, цитаты, позиции, связи и ограничения;
- `markdown`: содержимое файла;
- `filename`, `content_type`, `markdown_sha256`;
- `limits`: ограничения количества карточек, актов и байтов Markdown.

Пустой результат имеет `report.status = no_evidence`, `act_count = 0` и понятное
объяснение в файле. Ошибки: 400 — схема/дата, 401 — токен, 403 — доступ,
413 `case_report_limit` — объём, 503 `case_report_integrity` — неверные цитаты.
Повреждение исходного документа или материала также возвращает существующие
коды проверки целостности хранилища. Ошибки не включают пути БД или цитаты.

## Что содержит отчёт

Для каждого акта: суд, дата, инстанция, идентификатор, SHA-256 материала,
сведения о записанной проверке, дословные реквизиты и резолютивная часть.
Для позиции: сторона довода, цитата и ручное объяснение применимости.
Для связи: категория, целевой материал, его статус и отметка об устаревании.

Каждая цитата повторно сверяется с неизменяемым документом: SHA-256 текста,
`text[start:end] == quote`, принадлежность выбранному рабочему делу.
Смещения — индексы символов Python, с нуля, верхняя граница исключена.
Страницы вычисляются по пересечению с картой страниц; при её отсутствии
это прямо указывается. Выводятся URL и дата получения источника. Подлинность
URL и юридическая точность не удостоверяются автоматически.

Включаются цитаты, а не полные тексты всех документов. Однако длинная цитата
реквизитов может охватывать первую страницу. Перед передачей отчёта проверьте
данные дела: автоматического обезличивания здесь нет.

## Версии, время и целостность

Используется последняя версия каждой карточки. Предыдущие версии учитываются
в `excluded.superseded_versions`, но не изображаются отдельными инстанциями.
Текущие акты позднее `as_of` учитываются в `excluded.future_acts`, их текст
в отчёт не входит. Если один документ вручную заведён независимыми карточками,
они остаются отдельными материалами: устранение таких дублей не заявляется.

При замене целевой карточки прежняя связь не переназначается молча.
`target.superseded_by` и предупреждение требуют повторной проверки.
Квалификация проверяющих, смысл связи и применимость не подтверждены.
Одобрение прежней версии не переносится на новую.

Формирование синхронное, в одной ограниченной SQLite-транзакции: доступ,
материалы, проверки, текст отчёта и запись журнала относятся к одному снимку.
Внешних операций внутри транзакции нет. `snapshot_sha256` охватывает данные,
статусы и предупреждения, но исключает время формирования; два запроса без
изменения материалов имеют одинаковый отпечаток. `markdown_sha256` охватывает
точные UTF-8-байты конкретного файла, включая время формирования по Москве.

Отчёт не сохраняется отдельным документом сервера. Журнал содержит действие
`case_report_generated` и отпечаток, без цитат или токенов. Скачивание повторяет
формирование и оставляет ещё одно такое событие. Дата среза не восстанавливает
прошлое состояние проверки и не доказывает историческую доступность публикации.

## Ограничения объёма и представления

Не более 200 судебных карточек вместе с прежними версиями в рабочем деле,
20 актов в отчёте, 512000 байт Markdown. Лимит 200 применяется до отбора
номера судебного дела; в рабочем деле с большим числом карточек маршрут
возвращает 413 даже для небольшого отдельного спора. Эти пределы ограничивают
работу синхронной транзакции. Доказательства не обрезаются молча.

Пользовательские реквизиты экранируются как Markdown; цитаты и заметки помещаются
в буквальные блоки с ограждением длиннее любых обратных кавычек внутри текста.
Это сохраняет цитату и предотвращает её превращение в разметку отчёта.
Интерфейс использует `textContent`, затем скачивает тот же текст через Blob.

## Источники и незакрытые работы

По делу А40-255028/2022 выполнены точные поиски PDF и поиск по официальным
доменам; проверены публичная картотека и сайты апелляционного суда и округа.
Картотека вернула страницу проверки, сайты — HTML-страницы, не нужные акты.
Новые оригиналы нижестоящих решений не получены. Вторичные публикации не
переведены в статус первичных полных текстов. Реестр:
[CASE_REPORT_SOURCE_ATTEMPTS_2026-11-09.json](CASE_REPORT_SOURCE_ATTEMPTS_2026-11-09.json).
Архив остаётся прежним: семь официальных PDF, 90 страниц.

Отчёт показывает отсутствие подтверждённой полноты судебной истории,
непроверенное последующее движение дела и необходимость проверки применимости.
Он не объявляет направление на новое рассмотрение окончательным выигрышем.
Полные истории законодательства, независимое юридическое принятие 90 задач,
SSO и шифрование хранилища не входили в этот этап.

## Воспроизведение технической проверки

```sh
python -m unittest discover -q
python scripts/workspace_acceptance.py
python scripts/acceptance.py
python scripts/verify_primary_archive.py --parse-pdfs
node scripts/test_workspace_report.cjs
python scripts/browser_acceptance.py
```

Node VM проверяет реальную логику страницы с минимальной моделью DOM:
предпросмотр/скачивание, отзыв доступа, изменение снимка, сброс состояния.
Это не браузерная проверка оформления или взаимодействия с настоящим DOM.
Браузерный прогон, Docker, внешняя модель и GitHub Actions отмечаются отдельно;
синтаксис JavaScript и тесты упаковки не заменяют их выполнение.

Текущий результат: **541 тест, 26 прежних и 52 workspace HTTP-проверки**;
семь PDF повторно извлечены с совпадением текстов и карт страниц.
[CASE_REPORT_ACCEPTANCE_1_20_2026-11-09.json](CASE_REPORT_ACCEPTANCE_1_20_2026-11-09.json).
Реальный браузер заблокирован отсутствием Chromium; Docker и внешняя модель
не проверены. Эти статусы не считаются техническим или юридическим успехом.
