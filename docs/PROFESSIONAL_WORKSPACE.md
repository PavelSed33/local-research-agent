# Папка дела и экспертная проверка — API 1.23

## Защита интерфейса при смене пользователя или дела

Все запросы рабочего пространства проверяют поколение подключения, токен и
выбранное дело после получения и разбора ответа. Смена токена, дела или повторное
подключение отменяет использование старого ответа, даже если затем вернуть прежние
значения. Запоздавшие результаты поиска, документы и оригиналы не отображаются
и не скачиваются. Локальное чтение файла перед запросом также не может продолжить
действие с новым токеном. При смене дела поля документа, список документов,
условия скрытия и предыдущие результаты очищаются сразу, включая активный запрос.

Это отмена использования результата в интерфейсе: уже отправленная серверная
операция может завершиться. После сообщения о смене контекста повторите подключение
или обновите нужный список перед повторной записью.

Регрессии выполняются в Node VM, а не в браузере. Результат текущего этапа:

## Включение

Старый локальный режим продолжает работать без БД. Рабочее пространство
включается явно через WORKSPACE_DB. Оно сохраняет тексты, оригиналы,
экспертные материалы и оценки; файл БД и его резервные копии содержат данные дел.

```sh
mkdir -p runtime
chmod 700 runtime
umask 077
python scripts/manage_workspace.py init --db runtime/workspace.db > runtime/admin.json
WORKSPACE_DB="$PWD/runtime/workspace.db" API_HOST=127.0.0.1 python api.py
```

Откройте `http://127.0.0.1:8080/workspace` и введите токен из локального
runtime/admin.json. Файл не включается в git; токен не следует публиковать.
Повторная первоначальная настройка существующей БД запрещена. В режиме
WORKSPACE_DB прежний общий API_TOKEN не даёт доступа: все вычислительные
маршруты используют индивидуальные токены. Публичные страницы не содержат
данных дел. Для сетевого развёртывания нужен HTTPS на входе.

Администратор создаёт участников и экспертов в интерфейсе либо через
`/workspace/users/create`. Новый токен показывается один раз. Эксперт получает
доступ к делу от владельца; администратор не получает автоматического доступа
к чужим документам. Не создавайте фиктивные экспертные подтверждения.

Сначала создайте дело, затем прочитайте файл и сохраните его. При сохранении
неизменённого файла `/workspace/documents/upload` повторно разбирает именно
сохраняемые байты, записывает SHA-256 оригинала и текста и сохраняет оригинал
под теми же правами доступа. Изменённый в форме текст сохраняется как отдельный
текстовый документ без подмены оригинала. Кнопка «Оригинал» загружает сохранённые
байты; их хеш проверяется при выдаче.

Материалы, оригиналы и экспертные решения неизменяемы через API: исправление
создаёт новую запись, прежнее одобрение при необходимости отзывается. Удаление
содержимого и резервных копий сейчас выполняет оператор по принятой политике
хранения; автоматического удаления дел API не предоставляет.

## PDF/OCR

Нужны локальные `pdfinfo`, `pdftotext`, `pdftoppm`, `tesseract`. На Debian/Ubuntu:

```sh
sudo apt-get install poppler-utils tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng
```

Если Tesseract уже установлен, языковые данные можно загрузить отдельно:

```sh
python scripts/install_ocr_languages.py
```

Загрузчик получает rus/eng и LICENSE из официального tesseract-ocr/tessdata_fast
по коммиту `87416418657359cb625c412a48b6e1d6d41c29bd` (Apache-2.0), сверяет
Git blob SHA и сохраняет в runtime/tessdata. Этот каталог используется
автоматически, если TESSDATA_PREFIX не задан. Никаких загрузок при запуске API
нет. `/documents/capabilities` показывает реально доступные инструменты и языки.
Модели OCR в git не включены; в Docker предусмотрены системные пакеты
(INSTALL_PDF_OCR=1 по умолчанию). Сам Docker в текущей среде не запускался.

Лимиты: 10 МиБ файла, 30 страниц текстового PDF, 10 страниц при OCR, 200000
символов текста. OCR включается явно; отсутствие rus не подменяется eng.
Карта страниц и цитаты относятся к разобранному тексту. Таблицы, печати,
рукописные элементы и сложная вёрстка требуют ручной проверки.

## Поиск и ответы по делу

`/workspace/search` принимает matter_id и query, возвращает до 12 фрагментов с
ID документа, SHA-256, страницами и абсолютными позициями в разобранном тексте.
FTS5 использует начала слов: например, «оплат» покрывает больше словоформ,
чем «оплата». Полнота поиска и понимание противоречий не гарантируются.

`/workspace/ask` добавляет question, demo и allow_cloud. demo=true только
показывает найденные материалы. В рабочем режиме каждый вывод требует
дословных цитат; неизвестные источники и выдуманные цитаты отклоняются.
Наличие цитаты не доказывает правильность вывода или отсутствие пропусков.

Облачная модель требует одновременно allow_cloud=true в запросе и
ALLOW_CLOUD_DOCUMENTS=true на сервере. По умолчанию рабочий анализ дела
разрешён только локальной модели. Предпросмотр скрытия данных не удостоверяет
обезличивание: имена и другие сведения следует проверить вручную. Сам анализ
не сохраняет чат в БД; журнал фиксирует действие без вопроса и текста ответа.

## Источники, редакции и судебные материалы

В интерфейсе выберите архивный источник и добавьте его в дело. Реестр:
fixtures/primary_sources/manifest.json. Сохраняются исходные PDF, SHA-256,
извлечённый текст, карты страниц, ссылки на официальные карточки и файлы.

| Документ | Страниц | Состояние копии |
|---|---|---|
| Пленум ВС РФ №49 от 25.12.2018, заключение и толкование договора | 16 | Получен 08.11.2026; актуальность не подтверждена. |
| Пленум ВС РФ №7 от 24.03.2016, ответственность за нарушение обязательств | 25 | Получен 09.11.2026; в заголовке есть упоминание изменений от 07.02.2017 №6. Последующая история не подтверждена. |
| Пленум ВС РФ №54 от 22.11.2016, обязательства и их исполнение | 18 | Получен 09.11.2026; актуальность не подтверждена. |

Итого: 59 страниц, 163520 символов извлечённого текста. Это архивные материалы
разъяснений суда, а не подтверждённый банк действующих редакций 15 актов.
Упоминание изменения в заголовке — только найденная цитата: изменяющий акт
и полнота последующей истории этим не подтверждаются.

`/workspace/sources/list` возвращает каталог без полных текстов. Повторный
импорт того же снимка в то же дело возвращает существующий document_id и
reused=true, включая параллельные запросы. Перед выдачей сохранённого ID
проверяются права и целостность оригинала. При повреждении серверного архива
возвращается 503/primary_archive_unavailable; обычные документы остаются доступны.

В контекст ответа по делу передаются дата получения и состояние архивной
копии; интерфейс показывает предупреждение о неподтверждённой актуальности.
Промпт запрещает представлять архивные нормы как подтверждённо действующие.
Эти ограничения не заменяют проверку поведения реальной модели.

Воспроизведение разбора всех трёх оригиналов:

```sh
python scripts/verify_primary_archive.py --parse-pdfs
```

Проверяются SHA-256, реквизиты на первой странице, карта страниц и совпадение
повторного извлечения текста. При другом результате извлечения возвращается
extraction_differs; исходный архив автоматически не перезаписывается.

`/workspace/evidence/add` создаёт досье edition/decision/benchmark. Формы полей:
examples/evidence_templates.json. Эти шаблоны не содержат готовых правовых выводов.
`/workspace/evidence/list` — очередь, `/workspace/evidence/read` — материал.

Для edition указываются акт, норма, документ, valid_from, valid_to и цитаты
оснований периода. valid_to исключён: [valid_from, valid_to). Даты границ
должны присутствовать в цитатах; смысл основания проверяет эксперт. При
одобрении нужна ссылка на первичный официальный источник, но сам URL не
является доказательством подлинности. Для выбора `/workspace/editions/select`
нужны matter_id, act_id, provision, as_of. Неодобренные и отозванные записи
не выбираются; пересечение периодов возвращает ambiguous без редакции.

Для decision суд, номер дела, дата и обозначение инстанции привязываются к
общей цитате. Исход и позиции цитируют тот же документ. Связь с предыдущим
актом должна относиться к тому же делу и подтверждаться цитатой последующего
акта с номером дела и датой исходного. Смысл «отменён/оставлен без изменения»
и сопоставимость обстоятельств автоматически не удостоверяются.
`/workspace/cases/timeline` исключает события после as_of и всегда сохраняет
complete_history=false до полноценной проверки всей цепочки.

## Экспертная проверка и измерение качества

`/workspace/evidence/review` требует роль reviewer, доступ к делу, другую
учётную запись относительно автора, заключение и четыре явных подтверждения:
происхождение, полнота, временная применимость, правовые выводы. Решения
approved/rejected/revoked добавляются в историю, не перезаписывают её.
В интерфейсе есть очередь и форма решения. Квалификацию и реальную независимость
человека необходимо обеспечить организационно; приложение их не удостоверяет.
review_recorded не меняет глобальные legal_acceptance/verified на true.

Эталон содержит вопрос, дату, ожидаемый ответ, существенные риски, запрещённые
выводы и цитаты. Ручная оценка `/workspace/evaluations/record` возможна только
для одобренного эталона: correctness 0–4, индексы missed_risks, число
unsupported_claim_count и пояснение. Ориентиры шкалы: 0 — неверно, 1 — крупные
ошибки, 2 — частично, 3 — небольшие недостатки, 4 — обоснованно по проверенным
материалам. Это оценка эксперта, а не автоматическая гарантия.

`/workspace/evaluations/metrics` считает среднюю оценку, долю пропущенных
обязательных рисков и число неподтверждённых утверждений. Повтор той же оценки
тем же экспертом запрещён; оценки по отозванным эталонам исключаются.
Отсутствие оценок возвращает null, а не 100% качества. Старые 90 задач доступны
в fixtures/legal_benchmarks.json для подготовки независимой проверки.

## Доступ, аудит и проверка

Роли дела: owner управляет участниками и передачей владения, editor добавляет
материалы, viewer читает и анализирует. `/workspace/tokens/rotate` выдаёт новый
токен и отзывает старые. `/workspace/matters/transfer` передаёт дело существующему
участнику. Пользователя с принадлежащими ему делами нельзя отключить до передачи.
Сессии и ID отмены изолированы по пользователю. Отзыв доступа проверяется перед
выдачей позднего ответа по делу; уже переданные клиенту/провайдеру данные не отзываются.

`/workspace/audit` содержит только идентификаторы и действия; SQL-триггеры
запрещают перезапись/удаление журнала, а цепочка хешей выявляет изменения:

```sh
python scripts/manage_workspace.py verify-audit --db runtime/workspace.db
python scripts/workspace_acceptance.py
python scripts/acceptance.py
python -m unittest discover -q
```

Файлы SQLite создаются с правами 0600. Это не шифрование. Оператор с полным
доступом к файлу может изменить схему/перестроить цепочку; для более сильного
аудита нужна внешняя защищённая фиксация. Резервировать нужно согласованную
SQLite-БД с учётом WAL, а не копировать активный файл без процедуры бэкапа.

## Выбор редакции в анализе и задания для эксперта (API 1.17)

В форме анализа укажите дату ситуации, обновите список норм и выберите до
трёх норм с записанным одобрением. `/workspace/ask` принимает `as_of` и
`editions: [{"act_id": "...", "provision": "..."}]`. Сервер выбирает по
интервалу `[valid_from, valid_to)` и добавляет фрагмент выбранного документа
даже при отсутствии поискового совпадения. Если нет единственной одобренной
редакции — HTTP 409 `reviewed_edition_required`. Перед выдачей результата
сервер заново проверяет редакцию и запись проверки в транзакции; отзыв,
новая проверка или пересечение дают HTTP 409 `edition_review_changed`.
Выбор касается только явно указанных норм. Одобрение аккаунта не удостоверяет
квалификацию, полноту истории или правильность модельного вывода.

В разделе «90 заданий» кнопка подготовки переносит неизменяемые снимки
`fixtures/legal_benchmarks.json` в выбранное дело. Повторный импорт идемпотентен;
изменения шаблонов отмечаются счётчиком, сохранённые задания не перезаписываются.
Ответов и одобрений при импорте не создаётся. Откройте задание, введите ответ,
риски и недопустимые выводы, добавьте точные цитаты документов этого дела.
Сохранение создаёт неизменяемый benchmark-черновик. Новая версия создаёт новый
материал без переноса прежнего одобрения. Проверяющий работает через очередь
из другой учётной записи с ролью reviewer; самостоятельное одобрение запрещено.

Маршруты: `/workspace/benchmarks/import` и `/list` принимают `matter_id`;
`/read` — `task_id`; `/draft` — `task_id`, `expected_answer`, `required_risks`,
`forbidden_claims`, `citations`. Для повторного сохранения обязателен
`previous_artifact_id`; устаревшая версия даёт 409 `benchmark_task_changed`.
Импорт и сохранение требуют owner/editor, чтение доступно viewer.
Снимки и действия привязаны к делу, их хеши и журнал проверяются локально.

Все 90 реальных юридических приёмок остаются открытыми. Статус
`review_recorded` означает только записанное одобрение последнего черновика
другим аккаунтом; `legal_acceptance` остаётся false. Разные версии материала
имеют отдельные оценки, метрики API считаются по материалам, не по уникальным
задачам. Для приёмки набора нужно отдельно проверить все последние версии.

Попытки получения первичных документов 09.11.2026 не дали новых архивных
текстов: pravo.gov.ru и сервис поиска Минюста вернули ошибки/таймауты,
публичная PDF-ссылка КАД вернула HTML с капчей, список актов ВС — HTTP 503.
HTML не сохранён как судебный PDF; капча не обходилась. В архиве остаются
три PDF Пленума, а не подтверждённые редакции кодексов или индивидуальные дела.

## Отдельные судебные акты (API 1.18)

09.11.2026 в оригинальном PDF получены из `vsrf.ru/lk/practice/stor_pdf_ec/`:

| Определение | Дело | PDF, страниц | Тема для дальнейшего экспертного анализа |
|---|---|---:|---|
| 307-ЭС24-20538 от 28.02.2025 | А56-24586/2024 | 10 | Поставка, неустойка, оспаривание третейского решения |
| 307-ЭС25-3481 от 04.09.2025 | А56-119496/2023 | 8 | Сроки поставки, документация, мораторий |
| 305-ЭС23-19099 от 29.01.2024 | А40-255028/2022 | 7 | Аванс и срок поставки |
| 305-ЭС18-10125 от 13.12.2018 | А40-52603/2017 | 6 | Убытки, стоимость утраченного товара, НДС |

Это четыре отдельных дела, не четыре инстанции одного дела. В PDF есть
упоминания нижестоящих актов и мотивы отмены/сохранения их результатов.
Их оригиналы и события после определения ВС в архив не включены. Итог
реманда нельзя считать окончательным выигрышем стороны. Темы в таблице —
ориентиры для чтения, не готовые заключения о применимости.

Каталог проверяет номер определения, номер дела на первой странице, дату,
дословную резолютивную часть после «определила:», хеши и полную карту страниц.
Номер вида 307-ЭС25-3481 поддерживается отдельно от номера постановления
Пленума. Дата в цитатах досье может быть записана по-русски словами;
оригинальная цитата остаётся дословной, позиции ссылаются на неизменённый текст.

После выбора отдельного определения кнопка «Создать черновик карточки»
вызывает `/workspace/sources/decision-draft` с `matter_id` и `source_id`.
Оригинал сохраняется в деле, затем создаётся черновик decision с цитатами
реквизитов и результата. Повторные и параллельные запросы возвращают одну
карточку; существующая проверка не сбрасывается. Позиции и связи остаются
пустыми для последующей экспертной работы. Одобрение не создаётся.
Постановление Пленума этим маршрутом в отдельное дело не превращается.

`/workspace/ask` с `as_of` исключает найденные фрагменты этих архивных
определений, если `decision_date > as_of`. Счётчик относится к фрагментам,
а не делам. Первичный поиск ограничен восемью фрагментами; после исключения
не выполняется исчерпывающий перебор всей базы. Вручную добавленные документы
без такой архивной даты автоматически не датируются. Прямой поиск дела
продолжает показывать документы для самостоятельного исследования.

Новый архив: семь PDF, 90 страниц. Их получение не подтверждает актуальность
всех цитируемых норм, полноту судебной истории или независимую юридическую приёмку.

## Дополнение судебной карточки и история (API 1.19)

Раздел «Позиции и связи судебных актов» позволяет открыть последнюю карточку
и полный текст, добавить дословные позиции и объяснение их применимости,
связать карточку с другим уже загруженным актом этого дела. Список целей
показывает номер дела, дату, суд и статус проверки; в форме исключены сам акт,
другое дело и более поздние акты. Сервер повторно проверяет доступ и все ссылки.
Доступны supporting/opposing/distinguishing для позиций и
appeal/upheld/reversed/remanded для связей. Эти обозначения — ручная разметка,
не результат автоматической юридической квалификации.

`POST /workspace/cases/revise` принимает `artifact_id` текущей версии,
`positions` и `links` в той же форме, что decision в `/workspace/evidence/add`.
Цитата состоит только из `document_id` и `quote`; дополнительные вычисленные
поля старого ответа нужно убрать. Обе коллекции передаются целиком, до 20
элементов каждая; удаление заметки делается исключением её из новой коллекции.
Реквизиты и цитата резолютивной части копируются из прежнего неизменяемого
материала и этим маршрутом не редактируются. Новая версия всегда имеет draft,
прежнее одобрение и оценки на неё не переносятся. Нет изменений — HTTP 400.

Запись версии и связь с предшественником выполняются в одной SQLite-транзакции.
У одного предшественника только один преемник; параллельный или устаревший
запрос получает HTTP 409 `decision_version_changed`. Реестр версий запрещает
UPDATE/DELETE триггерами. Редактор или владелец может дополнить карточку,
наблюдатель — только читать. Прежние материалы и проверки сохраняются;
`/workspace/evidence/read` возвращает `version` с root_artifact_id,
previous_artifact_id и superseded_by. Очередь показывает последние версии.
Одобрить заменённую версию нельзя. Самостоятельное одобрение автором новой
версии по-прежнему запрещено; профессиональная квалификация не удостоверяется.

Новая связь должна цитировать выбранный акт, номер того же дела и дату
целевого акта. Не принимаются повторяющиеся позиции/связи, ссылка на тот же
документ, чужое дело, будущий акт или заменённая версия цели. Это проверки
текста и структуры; они не доказывают правильность категории связи.
Если цель дополнена позднее, прежняя связь не переписывается автоматически.
История сообщает target_superseded_by и requires_expert_review; одобрение
карточки со ссылкой на заменённую цель блокируется кодом decision_target_changed.
Нужно открыть последнюю цель и сохранить проверенную новую версию исходной
карточки. Самостоятельно перепривязывать или удалять чужую заметку сервер не будет.

`/workspace/cases/timeline` показывает последние версии на `as_of`, цитаты
исходов, relationships, число исключённых будущих актов и прежних версий.
Повторные версии одного документа не изображаются отдельными инстанциями.
Полнота истории и правовой смысл связей остаются неподтверждёнными.

Поиск 09.11.2026 по номерам четырёх дел и официальным доменам не дал новых
оригиналов нижестоящих актов. Найденные вторичные карточки и резолютивная
часть без полного первичного текста не включены в архив как полные решения.
Архив остаётся прежним: семь PDF, 90 страниц; законодательные истории и
проверенные юристом эталоны этим изменением не закрыты.
