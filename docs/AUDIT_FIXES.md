# Исправления по аудиту агента

7 ноября 2026 года · API 1.7.

## 1. Статья и ссылка в ответе /ask

До исправления отчёт мог ссылаться на источник [1], не содержащий статьи, и проходить проверку за счёт наличия статьи в другом, не указанном источнике [2].

Теперь проверяются только номера источников из того же предложения или пункта, где упоминается статья. Ссылка из соседнего предложения, абзаца или элемента списка не заимствуется. Непосредственная ссылка после завершающей точки или закрывающей кавычки относится к предшествующему предложению. Десятичные номера и основные сокращения не разрывают предложение.

Для каждой упомянутой статьи должен найтись хотя бы один источник из указанной группы, содержащий ту же статью и распознаваемое обозначение того же закона/кодекса в контексте статьи либо заголовке источника. Если в одном фрагменте названы разные акты и связь неоднозначна, агент требует разделить утверждения. Отсутствующая или неверная ссылка не заменяется поиском по остальным материалам.

Модель получает требования к такому формату. Если первичный отчёт их нарушает, срабатывает существующая попытка исправления. Если исправленный отчёт тоже нарушает связь, возвращается ошибка, а не непроверенный отчёт.

Это проверка ссылочной и текстовой связи, не смысловое доказательство правового вывода. Она не устанавливает действующую редакцию, исключения, подлинность источника и применимость к обстоятельствам. Неподтверждённые периоды и юридическая приёмка по-прежнему остаются неподтверждёнными.

## 2. Недоверенные поля модели в старых маршрутах

`/review` больше не возвращает произвольные поля объектов риска. Сохраняются только предусмотренные строковые поля; `verified` и `lawyer_reviewed` задаёт программа как false. Непроверенные `legal_basis` отбрасываются: старый маршрут не получает правовые источники и возвращает `no_legal_evidence`.

Одинаковая политика применяется к первичному и исправленному результату, а также к прямому Python-вызову `review_contract`. Специализированный `/review/legal` использует общий конструктор риска, после чего добавляет только отдельно проверенные правовые цитаты, сохраняя неподтверждённость периода и юридической применимости.

`/extract` и `extract_entities` также возвращают только предусмотренные поля сущностей, срока и подсудности. Вложенные самоназначенные подтверждения, заключения, произвольные основания и другие дополнительные объекты не передаются клиенту. `quote_checked=true` означает только прохождение проверки совпадения цитаты документа. Это не удостоверение всей интерпретации извлечённого значения. Цитаты, срок и название суда должны иметь строковый тип; вложенный объект вместо строки требует исправления или отклоняется.

## 3. Сопутствующие изменения

- Для `/review`, `/extract` и `/review/legal` используется единый верхний предел 200000 символов текста. Превышение отклоняется до проверки разрешения передачи и создания модели. Лимиты HTTP и DOCX продолжают действовать отдельно.
- OpenAPI описывает HTTP Bearer в `components.securitySchemes`. Схема конкретного сервера указывает требование токена для POST при включённом API_TOKEN и отсутствие такого требования в разрешённом локальном режиме без токена. Секрет в схему не включается.
- Контейнер запускает приложение с UID/GID 10001 вместо root. Каталог `/data` получает соответствующего владельца при сборке. Для подключённого существующего тома или bind mount владелец развёртывания должен обеспечить права записи этому UID/GID. Реальная сборка и запуск контейнера в текущей среде не подтверждены.

## 4. Проверка и открытые ограничения

Добавлены отдельные регрессии: первоначальный пример неверной ссылки, правильная ссылка, соседние предложения/абзацы/списки, десятичная статья, неоднозначные акты, группы ссылок, отказ после неудачного исправления, самосертификация модели, обе ветки исправления JSON, вложенные объекты, ограничения текста и реальные локальные HTTP-запросы с проверкой OpenAPI в двух режимах авторизации.

Не заявляются завершёнными: смысловая верификация всех правовых утверждений, полный корпус нормативных редакций, юридические эталоны, общий дедлайн/отмена исследования, многопользовательская изоляция, браузерная приёмка и рабочий запуск внешних провайдеров. Эти изменения закрывают конкретные подтверждённые дефекты, а не всё правовое ТЗ.

Проверка: полный локальный набор — **315 тестов**, 16/16 синтетических структурных сценариев, compileall, синтаксис JavaScript и проверка корпуса без ошибок. После оптимизации разбора предложений и однократной индексации статей источников повторно выполнены целевые регрессии и существующие проверки исследовательского цикла, извлечения, договоров и упаковки. Контрольные воспроизведения исходных двух дефектов теперь дают отклонение неверной ссылки и программные false для вложенных статусов.
