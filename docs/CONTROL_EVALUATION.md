# Контрольные наборы и сравнение версий — API 1.29

Цель — измерять изменения на одних и тех же задачах и не подавать контрольные
ответы в обучающую память. Сравнение использует экспертные оценки; реального
улучшения юридического качества этим изменением не установлено.

## Подготовленное разделение задач

`fixtures/quality_control_plan.json` делит существующие 25 синтетических задач
на 10 контрольных и 15 кандидатов для обучения. Контроль: SERV-P02, P03, P08,
P10, P12, P14, P21, P22, P24, P25 (у всех префикс SERV-).
Темы включают недостающие приложения, противоречащие цены, приёмку/возражения,
отказ, ответственность, редакции норм, квалификацию договора и инструкцию в тексте.

Ответы остаются пустыми и не приняты юристом. После импорта задания из этой
контрольной части резервируются автоматически: обучающая память исключает
их текущие эталоны и вопросы всех версий, даже до создания отдельного набора.
Ошибочный или недоступный файл плана останавливает подбор опыта.

## Работа в интерфейсе

1. Подготовьте реальные ответы и источники. Другой эксперт проверяет эталоны;
   приложение не удостоверяет его профессиональную квалификацию.
2. Откройте «Контрольный набор и сравнение версий», обновите список, выберите
   одобренные эталоны и зафиксируйте состав. Это делает владелец или редактор дела.
   Можно создать свой набор, не ограниченный синтетическим планом.
3. Только после фиксации получите ответы двух версий и запишите экспертные оценки
   с разными метками запуска. Не включайте ответы контрольных задач в документы
   или иные обучающие примеры. Память сама исключает закреплённые эталоны и точные
   дубликаты их вопросов; перефразирования требуют отдельного контроля.
4. Укажите те же метки и нажмите «Сравнить экспертные оценки».
5. Если обе версии выдали дословно одинаковый ответ, оцените его один раз и
   используйте форму «Записать совпадение ответов» для второй метки. Это явное
   заявление эксперта о совпадении; второй фиктивной оценки не создаётся.

## Как считается результат

Набор хранит идентификаторы эталонов, хеши их содержимого и точных записей
одобрения. Состав не редактируется и не снимается с контроля через API.
Включение эталона в контроль блокирует и ранее подобранный опыт: старый запрос
или скачивание отчёта с таким опытом должны быть сформированы заново.

Для каждой задачи нужны обе метки, одинаковый состав экспертов и ровно одна
оценка каждого эксперта для каждой метки. Оценки до создания набора не учитываются.
Несколько ответов с одной меткой не позволяют выбрать лучший: результат будет
неполным. Для нового эксперимента используйте новые метки.

Метрики: правильность 0–4, число пропущенных рисков и число неподтверждённых
утверждений. Сначала усредняются оценки экспертов внутри задачи, затем задачи
получают равный вес. Дополнительные оценки одной задачи не увеличивают её вес.

Любое снижение правильности, новый пропущенный риск или рост числа
неподтверждённых утверждений **в любой отдельной паре** отмечает регрессию,
даже если средние показатели улучшились. Проверка не позволяет компенсировать
ухудшение одного показателя улучшением другого.
Сравниваются и индексы пропущенных рисков: замена одного пропуска другим
отмечает регрессию, даже если их общее число не изменилось.

| `gate` | Значение |
|---|---|
| `regression` | Есть ухудшение хотя бы одной пары; предложение принять изменение блокируется |
| `incomplete` | Не хватает задач/экспертов или оценки неоднозначны; вывод об улучшении блокируется |
| `no_regression` | Все задачи заполнены и ухудшений по записанным показателям нет; можно передать результат эксперту |

`improvement_observed=true` означает наличие улучшенного показателя при полном
наборе без регрессии. Это не статистическое доказательство превосходства.
`adoption_approved`, `quality_improvement_proven`, `run_provenance_verified` и
`legal_acceptance` всегда `false`: автоматического принятия новой версии нет.
Факт реального запуска модели и происхождение вставленных ответов не удостоверяются.

## API

- `/workspace/quality/sets/create`: `matter_id`, `title`, `benchmark_ids` (1–100).
- `/workspace/quality/sets/list`: `matter_id`.
- `/workspace/quality/compare`: `matter_id`, `set_id`, `baseline_label`, `candidate_label`.
- `/workspace/quality/runs/register`: `matter_id`, `set_id`, `evaluation_id`, `run_label`,
  `same_answer_declared=true`. Только эксперт может связать собственную оценку
  с другой меткой дословно одинакового ответа.

Все маршруты — POST с индивидуальным токеном. Сравнивать может участник с текущим
доступом к делу. Сырые ответы в результат сравнения не включаются; выдаются
показатели, идентификаторы оценок и отпечатки ответов для проверки происхождения.
Отзыв или повторное одобрение эталона останавливает сравнение старого набора.
Изменение оценки, связанной с заявлением об одинаковом ответе, тоже блокирует его.

До 50 наборов по 256 КиБ на дело, до 200 оценок на задачу и до 1000 привязок
одинаковых ответов на дело. Превышение останавливает операцию без усечения.
Наборы и привязки хранятся в существующей таблице artifacts и входят в резервные
копии; схема БД не меняется. Результат сравнения рассчитывается заново по текущим
оценкам, а не сохраняется как независимое заверение.

Контрольный набор не доказывает полноту источников или юридическую корректность.
Пока нет реальных одобренных эталонов и независимых оценок, доступна только
техническая проверка механизма на синтетических данных.
