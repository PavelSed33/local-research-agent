# Правки в исходном DOCX — API 1.22

Добавлен отдельный режим `/documents/redline`. Он получает исходный DOCX и
явные замены, записывает настоящие элементы вставок и удалений WordprocessingML
и возвращает новый файл. Исходный файл и документы дела не перезаписываются.

## Работа в интерфейсе

В `/workspace` откройте «Правки в исходном Word», выберите DOCX, укажите
уникальную исходную цитату и замену. Пустая замена означает удаление.
Добавьте необходимые замены и нажмите «Скачать DOCX с исправлениями».
Автор по умолчанию — «Правовой агент»; его можно изменить. Это подпись в
метаданных исправления, не подтверждение квалификации или юридического одобрения.

Цитата может быть разбита на несколько текстовых фрагментов с разным
оформлением, но должна находиться в одном обычном абзаце или абзаце ячейки
таблицы. Вставленный текст наследует оформление начала цитаты. Удалённые
части сохраняют своё оформление внутри `w:del` с текстом `w:delText`.
Новый текст хранится внутри `w:ins`. Переключатель отслеживания будущих правок
в настройках исходника не меняется; уже созданные исправления остаются в файле.

Содержимое всех остальных частей ZIP-пакета сохраняется побайтно:
стили, нумерация, изображения, колонтитулы, комментарии и свойства документа.
Меняется только `word/document.xml`; сохранены пространства имён, таблицы,
свойства абзацев и текст вне замен. Сжатые байты всего ZIP могут отличаться.
Пагинация и переносы строк могут измениться из-за длины нового текста и показа
удалений. Это сохранение структуры и свойств, не обещание неизменных страниц.

**Исходные метаданные и комментарии могут содержать персональные данные.**
Режим не является обезличиванием; сохраняемые свойства не объявляются очищенными.
Перед передачей файла проверяйте его содержание, свойства и историю в Word.

## Маршрут

`POST /documents/redline`, обычная авторизация сервера; в режиме WORKSPACE_DB —
индивидуальный токен. Запрос выполняется в изолированном worker с существующими
дедлайнами/отменой. Перед выдачей результата повторно проверяется активность
пользователя. Файл передаётся самим вызывающим пользователем: маршрут не
читает документы из чужих дел и не принимает document_id.

```json
{
  "filename": "original.docx",
  "file_base64": "<base64 исходного DOCX>",
  "author": "Правовой агент",
  "replacements": [
    {"quote": "10 дней", "replacement": "15 рабочих дней"}
  ]
}
```

Ответ: `document_base64`, имя `redlined.docx`, SHA-256 исходного и нового
файла, количество замен, `word_track_changes: true`, `changed_parts` и
предупреждение о проверке. Модель и сеть не используются. Смена токена,
дела или файла очищает список замен; запоздалый результат не скачивается.

## Границы и отказы

- До 10 МиБ исходного и выходного ZIP, до 50 явных непересекающихся замен.
- Цитата и новый текст — до 20000 символов, без табуляций и разрывов строк.
  Переносы между абзацами не создаются; неизменённые прочие абзацы сохраняются.
- Цитата должна встречаться ровно один раз в основном тексте. Колонтитулы
  и сноски сохраняются, но не участвуют в автоматическом поиске замены.
- Поля, гиперссылки, закладки, изображения в редактируемом абзаце, текстовые
  блоки и специальные контейнеры отклоняются. Обычные таблицы поддерживаются.
- Существующие вставки/удаления и другие отслеживаемые изменения нужно сначала
  принять или отклонить в Word. Истории не объединяются автоматически.
- Макросы, вложенные объекты, подписанные пакеты, защищённые документы,
  внешние шаблоны и связи с данными отклоняются. Разрешённые внешние
  гиперссылки HTTP/HTTPS/mailto сохраняются, но не открываются сервером.
- Проверяются ZIP-дубликаты, размеры, пути, шифрование, основная связь пакета,
  тип содержимого, XML и запрет DTD/сущностей. Частичное применение при ошибке
  не возвращается; неоднозначная или неподдерживаемая замена даёт HTTP 400.

Это не полная поддержка любых документов Word: сложные объекты требуют
ручной работы. Простой экспорт `/documents/export` остаётся отдельным режимом
создания черновика без исходного оформления.

## Техническая проверка

Проверены замены через несколько фрагментов с жирным/курсивным оформлением,
в таблице, несколько замен в одном фрагменте, удаления, пересечения, дубликаты,
существующие изменения и опасные конструкции пакета. Принятие новых элементов
ревизии даёт ожидаемый новый текст; отклонение — исходный. Байты остальных
частей сравниваются с исходными.

Форматированный пример с таблицей, верхним/нижним колонтитулами и изображением
отрендерен LibreOffice до и после изменений. Обе страницы осмотрены: таблица,
колонтитулы и изображение сохранены, изменения видимы; обрезки/наложений нет.
Это визуальная проверка LibreOffice и структуры OOXML, не запуск Microsoft Word.

Воспроизводимый необязательный пример:

```sh
python scripts/build_docx_redline_fixture.py /tmp/docx-redline-qa
python -m unittest test_docx_redline test_workspace_http test_packaging -q
node scripts/test_workspace_report.cjs
```

Генератор примера требует python-docx и Pillow только в среде QA. Серверный
редактор использует стандартную библиотеку Python, новые runtime-зависимости
в Docker не добавлены. Для визуальной приёмки используйте DOCX-рендерер и
осмотрите изображения всех страниц исходника и результата.

Ориентиры формата: официальные описания Microsoft
[InsertedRun](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.insertedrun)
и [DeletedRun](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.deletedrun).

Доработка улучшает пятый пункт общего плана. Подтверждённые законодательные
истории, полные цепочки судебных инстанций, независимое принятие 90 задач,
реальная модель, SSO/шифрование и гарантированное обезличивание не объявляются
завершёнными этим изменением.

Результат текущего прогона: **553 теста, 26 прежних и 54 workspace HTTP-проверки**.
[ORIGINAL_DOCX_ACCEPTANCE_1_22_2026-11-09.json](ORIGINAL_DOCX_ACCEPTANCE_1_22_2026-11-09.json).
Реальный браузер, Docker и внешняя модель остаются отдельно непроверенными.
