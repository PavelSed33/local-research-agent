# Источники для проверки договора поставки

Подборка от 28 ноября 2026 года охватывает обычную поставку товаров между предпринимателями. Дата снимка определяет, когда агент получил текст. Применимость конкретной редакции зависит от даты заключения договора, спорного события и переходных положений.

## Проверка через API

Отправьте следующий JSON в `POST /review/legal`. Поле `supply_references` в ответе содержит выдержки, номера статей и сведения об источниках. При дате ситуации раньше 28 ноября 2026 года агент исключает этот снимок. При неопределённой цели покупки или особом режиме договора агент запрашивает факты перед подбором источников.

```json
{
  "document": "Поставщик передаёт покупателю оборудование партиями по согласованной спецификации.",
  "profile": "business",
  "contract_type": "supply",
  "as_of": "2026-11-28",
  "demo": true,
  "facts": {
    "both_businesses": true,
    "goods_nonpersonal_purpose": true,
    "mixed_contract": false,
    "special_regime": false
  }
}
```

## Что проверять в договоре

| Условие | Вопрос к документу | Статьи ГК РФ для сверки |
|---|---|---|
| Предмет и количество | Как связаны договор, заказ и принятая спецификация? | 432, 455, 465, 506, 507 |
| Сроки, доставка и выборка | Где передают партию, кто организует доставку, как подтверждают уведомление о готовности? | 314, 458, 508–511, 515 |
| Приёмка и качество | Как фиксируют расхождения, извещают поставщика и оформляют хранение или замену? | 469, 474, 475, 483, 513, 514, 518–520 |
| Расчёты | С какого события начинается срок оплаты и как стороны определяют базу неустойки? | 328, 330, 333, 395, 486, 487, 516, 521 |
| Отказ и убытки | Какие условия нарушены, когда доставлено уведомление и чем подтверждены расходы? | 165.1, 310, 393, 450.1, 453, 523, 524 |

Для части I сохранены выдержки из 73 статей, для части II — из 57, включая все статьи 506–524. Для каждой статьи зафиксированы источник, SHA-256 извлечённого текста и положение в исходном HTML. Печатные версии банка актов Президента России были получены по HTTP. ## Восстановление судебного архива

В чистом клоне выполните команды из корня репозитория. Для повторного извлечения текста установите Poppler с утилитами `pdfinfo` и `pdftotext`.

```sh
export PRIMARY_ARCHIVE_PDF_DIR="$PWD/fixtures/primary_sources"
python scripts/restore_primary_archive.py --output-dir "$PRIMARY_ARCHIVE_PDF_DIR"
python scripts/verify_primary_archive.py --parse-pdfs
```

Скрипт восстанавливает семь PDF из закреплённой версии архива проекта. Для каждого исходного файла манифест содержит официальный адрес и SHA-256. Проверка с Poppler сопоставляет извлечённый текст и разметку всех 90 страниц с эталоном проекта. [Архивный коммит](https://github.com/PavelSed33/local-research-agent/tree/21be8dd021ef392623e30a25085b255aae2871e5/fixtures/primary_sources) · [Манифест](../fixtures/primary_sources/manifest.json)

Запустите API с рабочим пространством. Авторизованный `POST /workspace/sources/list` с телом `{}` вернёт семь записей, `complete: true` и пустой `missing_original_ids`. Для Docker смонтируйте каталог с PDF только для чтения и укажите путь **внутри контейнера** через `PRIMARY_ARCHIVE_PDF_DIR`. [Запуск в Docker](../README.md#запуск-в-docker)
