# Юридический ИИ-помощник по законодательству РФ

Локальный прототип, который принимает правовой вопрос, ищет нормы в правовых источниках, отдельно проверяет последние изменения и готовит ответ со ссылками.

## Что умеет

- формировать до 5 первоначальных поисковых запросов;
- искать материалы через Tavily по заданному списку правовых сайтов;
- оценивать полноту найденных норм и выполнять до двух циклов дополнительного поиска;
- **при каждом запуске отдельно искать последние изменения, новые редакции, даты вступления в силу и сведения об утрате силы**;
- указывать дату проверки изменений;
- формировать ответ только на основании найденных материалов;
- проверять обязательные разделы, номера цитат и отсутствие посторонних ссылок;
- один раз исправлять ответ, если автоматическая проверка обнаружила ошибки;
- сохранять ответ в Markdown и подробный журнал в JSON;
- принимать запросы по HTTP API (`POST /ask`, `GET /health`) для интеграции в «завод агентов»;
- работать в демонстрационном режиме без ключей и внешних запросов.

## Важные ограничения

Агент не «знает все законы» и не заменяет полноценную профессиональную правовую базу. Он ищет доступные тексты при каждом обращении. Результат является информационной справкой, а не индивидуальной юридической консультацией. Автоматическая проверка не гарантирует актуальность нормы: важные решения необходимо проверять по официальным текстам и при необходимости обсуждать с юристом.

По умолчанию поиск ограничен доменами:

- `pravo.gov.ru` — официальный интернет-портал правовой информации;
- `www.consultant.ru` — справочные тексты и редакции КонсультантПлюс;
- `www.garant.ru` — правовые материалы Гаранта.

Список можно изменить через `LEGAL_SEARCH_DOMAINS`. Наличие сайта в списке не означает, что каждый найденный документ является официальной или действующей редакцией.

## Требования

- Python 3.10 или новее;
- для реальной работы — ключ языковой модели с OpenAI-совместимым API и ключ Tavily;
- для демонстрационного запуска ключи не нужны;
- сторонние Python-библиотеки не требуются.

## Быстрая проверка

```bash
python agent.py "Какие документы нужны для регистрации ИП" --demo
```

В Windows при необходимости используйте `py` вместо `python`.

В папке `результаты` появятся:

- `ответ-<дата>.md` — правовой ответ, дата проверки, предупреждение и источники;
- `журнал-<дата>.json` — запросы, материалы, дополнительные циклы и отдельная запись о проверке изменений.

Демонстрационный режим использует условные материалы и не даёт реального правового заключения.

## Настройка реальной работы

1. Скопируйте `.env.example` в `.env`.
2. Укажите ключи и модель:

```dotenv
LLM_API_KEY=ваш_ключ
LLM_MODEL=название_доступной_модели
LLM_BASE_URL=https://api.openai.com/v1
TAVILY_API_KEY=ваш_ключ_tavily
LEGAL_SEARCH_DOMAINS=pravo.gov.ru,www.consultant.ru,www.garant.ru
```

Если используется другой OpenAI-совместимый сервис, замените `LLM_BASE_URL` на базовый адрес без `/chat/completions` в конце.

3. Запустите помощника:

```bash
python agent.py "Может ли работодатель изменить график без согласия работника" --queries 3 --sources 8
```

Параметры:

- `--queries` — от 1 до 5 первоначальных запросов;
- `--sources` — от 1 до 10 источников;
- `--output-dir` — другая папка для результатов;
- `--demo` — локальная проверка без API.

## HTTP API

Файл `api.py` поднимает HTTP-сервис поверх той же логики агента — это универсальный способ подключить помощника к «заводу агентов» или любой другой системе. Обязательная проверка последних изменений выполняется при каждом запросе, как и в консольном режиме.

Запуск:

```bash
python api.py
```

Эндпоинты:

- `GET /health` — проверка работоспособности. Возвращает `status`, версию сервиса и флаги `llm_configured` / `tavily_configured`, чтобы «завод агентов» видел готовность конфигурации.
- `POST /ask` — правовой вопрос. Тело запроса:

```json
{
  "question": "Может ли работодатель изменить график без согласия работника",
  "queries": 3,
  "sources": 6,
  "demo": false
}
```

Поля `queries` (1–5), `sources` (1–10) и `demo` необязательны. Ответ:

```json
{
  "answer": "# …маркдаун-ответ с источниками…",
  "sources": [{"title": "…", "url": "…"}],
  "checked_on": "2026-11-06",
  "disclaimer": "Информационная справка, а не индивидуальная юридическая консультация…",
  "demo": false,
  "report_file": "…",
  "journal_file": "…"
}
```

Проверка без ключей:

```bash
curl -s http://127.0.0.1:8080/health
curl -s -X POST http://127.0.0.1:8080/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "Какие документы нужны для регистрации ИП", "demo": true}'
```

Настройки API (через переменные окружения или `.env`):

- `API_HOST` — адрес прослушивания, по умолчанию `127.0.0.1`;
- `API_PORT` — порт, по умолчанию `8080`;
- `API_OUTPUT_DIR` — папка для отчётов и журналов, по умолчанию `результаты`;
- `API_TOKEN` — необязательный токен доступа (только латиница и цифры). Если задан, каждый запрос к `/ask` требует заголовок `Authorization: Bearer <API_TOKEN>`. `/health` остаётся открытым для проверок живости.

API-ключи модели и Tavily передаются только через переменные окружения и не попадают в ответы API.

## Запуск в Docker

```bash
docker build -t legal-research-agent .
docker run --rm -p 8080:8080 \
  -e LLM_API_KEY=ваш_ключ \
  -e LLM_MODEL=название_модели \
  -e TAVILY_API_KEY=ваш_ключ_tavily \
  -e API_TOKEN=секретный_токен_латиницей \
  -v legal-agent-results:/data \
  legal-research-agent
```

Или с файлом окружения: `docker run --rm -p 8080:8080 --env-file .env -v legal-agent-results:/data legal-research-agent`.

Отчёты и журналы сохраняются в томе `/data` (внутри контейнера `API_OUTPUT_DIR=/data/results`). Файл `.env` не копируется в образ — он исключён через `.dockerignore`.

## Структура ответа

1. Краткий ответ.
2. Правовое основание.
3. Актуальность и изменения.
4. Как применить к ситуации.
5. Ограничения.
6. Источники.

## Тесты

```bash
python -m unittest -v
```

Двадцать тестов проверяют разбор JSON, удаление дублей, структуру и ссылки ответа, его исправление, дополнительный поиск, обязательную проверку изменений и HTTP API (эндпоинты, валидацию запросов и авторизацию по токену). Тесты не обращаются к внешним сервисам.

## Дальнейшее развитие

Для более надёжной работы нужны подключение к полноценной правовой базе, автоматическое сравнение редакций, проверка даты вступления изменений в силу, судебная практика и мониторинг поправок по сохранённым вопросам. Не публикуйте `.env` и API-ключи.
